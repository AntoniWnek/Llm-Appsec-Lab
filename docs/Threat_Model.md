# Threat Model — Enterprise HR Copilot (OWASP LLM Top 10 2025)

## 1. System Overview & Synthetic Lab Assets

The Enterprise HR Copilot is an isolated security research laboratory simulating an internal recruitment assistant that queries an SQLite database (`data/hr_lab.db`), verifies candidate portfolio links, and summarizes uploaded `.pdf` or `.txt` resumes. All data and credentials in this repository are **100% synthetic**.

### Protected Laboratory Assets
1. **Confidential Executive Compensation (`board_salaries` table):** Synthetic executive records (`Marek Zielinski`, `Anna Wisniewska`, `Piotr Kaminski`), base salaries, bonuses, and the Canary Honeytoken (`CONF-HR-9921-X`).
2. **Simulated Cloud Metadata Credentials:** Synthetic AWS STS-formatted temporary credentials (`AccessKeyId: ASIA-HR-PROD-9921`, `SecretAccessKey: CANARY-CLOUD-IAM-KEY-8842-SECRET`). In `Vulnerable` mode, `fetch_portfolio_url` redirects metadata requests to the local mock listener (`http://127.0.0.1:8888/latest/meta-data/...`) or returns a synthetic fallback payload. No real AWS or GCP infrastructure is contacted.
3. **System Instructions & Internal Routing Logic:** Internal prompt directives and database schema definitions.
4. **Recruiter Browser Session:** The web client rendering Markdown responses generated by the assistant.
5. **SIEM Security Audit Log (`data/telemetry.jsonl`):** The local historical record of security events, tool invocations, and detected Indicators of Compromise (IoCs).

## 2. Three-Domain Threat Taxonomy & Trust Boundaries

This threat model separates risks across **three distinct domains**, explicitly distinguishing the **Threat Actor (Initiator)** from the **Vulnerable Component / Architectural Weakness**:

### Domain 1: Internal User Threats (Unprivileged HR Recruiter as Threat Actor)
- **Trust Boundary:** Authenticated access to the Streamlit chat interface (`ATK-01` through `ATK-05`, and as the request initiator in `ATK-08`).
- **Authorization Scope:** Permitted to query public candidate profiles (`candidates` table) and verify public HTTPS portfolio repositories (`github.com`, `gitlab.com`, `linkedin.com`). **Unauthorized** to access `board_salaries`, execute arbitrary SQL DDL/DML, probe internal network endpoints, or exhaust inference compute budgets.
- **Threat Vectors:**
  - System prompt and restricted schema reconnaissance (`ATK-01`).
  - Privilege escalation by spoofing internal audit headers (`[HR-AUDIT-BENCHMARK]` in `ATK-02`).
  - Filter evasion via Base64 encoding (`ATK-03`) or Unicode zero-width character smuggling (`U+200B` in `ATK-04`).
  - LLM-driven SQL Injection (`UNION SELECT` in `ATK-05`).
  - Submitting internal/metadata URLs (`ATK-08` — where the recruiter or an injected document is the *initiator*, exploiting the runtime's unvalidated URL-fetching tool and network reachability described in Domain 3).
  - Request flooding and token-budget exhaustion (`OWASP LLM10:2025 Unbounded Consumption`).

### Domain 2: External Data Provider Threats (Unauthenticated Job Candidate as Threat Actor)
- **Trust Boundary:** Zero direct access to the internal network or chat UI. Interacts solely by submitting passive data artifacts (PDF/TXT resumes or application form fields).
- **Threat Vectors:**
  - **Indirect Prompt Injection via Off-Canvas PDF (`ATK-06`):** Submitting a `.pdf` resume (`data/poisoned_cv.pdf`) where adversarial instructions are placed at coordinates `(-5000, -5000)` outside the visible `MediaBox [0 0 612 792]`. When an innocent recruiter summarizes the CV, the payload attempts to hijack control flow and exfiltrate data via a Markdown image beacon.
  - **Second-Order (Stored) Prompt Injection via Database Row (`ATK-07`):** Injecting a dormant workflow trigger inside the `key_skills` column of candidate `Victor Reznov` in SQLite. The payload activates later when a recruiter queries the candidate's record.

### Domain 3: Execution Environment & Runtime Infrastructure Vulnerabilities (Vulnerable Components)
- **Trust Boundary:** The interaction between the LLM inference engine, the Python backend process, the SQLite C-driver, the host network stack, and the victim's browser DOM.
- **Environmental & Component Risks:**
  - **Stochastic LLM Variance & Unstructured Tool Emission:** Small local models (`qwen2.5:3b` on CPU) may emit raw JSON tool invocations inside text content instead of structured `tool_calls`, or refuse in plain text without invoking any tool.
  - **Shared Database File Co-location:** Both public (`candidates`) and confidential (`board_salaries`) tables reside inside the same SQLite database file (`data/hr_lab.db`). Without driver-level authorization (`sqlite3.set_authorizer`), any raw SQL connection shares full table read/write privileges.
  - **Agent Network Reachability (Vulnerable Component in `ATK-08`):** The backend Python process has network reachability to loopback services (`127.0.0.1`) and link-local addresses (`169.254.169.254`) unless restricted by an outbound URL validator and network firewall.
  - **Client Browser DOM Auto-Fetching:** Standard Markdown-to-HTML rendering in web UIs automatically issues HTTP `GET` requests for `<img>` tags.

## 3. Defense-in-Depth Mitigations & Boundary Enforcement (Hardened Mode)

In `Hardened` mode, superficial chat keyword filters are omitted so that security is enforced at **downstream tool-scope, schema validation, and database driver boundaries**:

| Boundary Layer | Component | Technical Implementation | Mitigated Risks |
| :--- | :--- | :--- | :--- |
| **Layer 1a: Input Normalization & Length Cap** | `src/guardrails.py` (`inspect_user_input`) | Strips invisible Unicode control characters (`U+200B`–`U+200F`, `U+FEFF`) and enforces `MAX_PROMPT_CHARS = 4000`. | `LLM01:2025` (Unicode TOCTOU) |
| **Layer 1b: In-Memory Sliding-Window Rate & Heuristic Token Budget Guard** | `src/guardrails.py` (`check_unbounded_consumption`) | Uses deterministic character/word heuristics (`estimate_token_count`) to enforce per-turn limits (`1200` estimated tokens), rolling 60s request frequency limits (`15` req/window -> `BLOCKED_RATE_LIMIT_EXCEEDED`), and cumulative window budgets (`6000` estimated tokens -> `BLOCKED_TOKEN_BUDGET_EXCEEDED`). | `LLM10:2025` (Unbounded Consumption / DoS) |
| **Layer 2: Task-Based Zero-Tool Scoping & XML Structuring** | `src/agent.py` & `src/guardrails.py` (`sandbox_cv_document`) | When `cv_attached=True`, `agent.py` omits tool definitions from the provider inference request for that turn (`active_tools = []`, passed as `tools=None`), while the backend dispatcher independently enforces tool authorization. Wraps resume data in `<untrusted_cv_data>`. | `LLM01:2025` (Indirect XPIA), `LLM06:2025` |
| **Layer 3a: Tool Registry Isolation & Pydantic Parameterized SQL** | `src/tools.py` (`search_candidates_safe`) | Detaches `run_raw_sql` (`BLOCKED_UNAUTHORIZED_TOOL`). Validates search parameters via `CandidateSearchParams` (Pydantic) and executes hardcoded parameterized SQL (`?` placeholders). | `LLM05:2025`, `LLM06:2025` |
| **Layer 3b: Database Egress Sanitizer** | `src/guardrails.py` (`sanitize_db_record_value`) | Scans string fields returned from SQLite rows before passing them into the LLM context, stripping dormant Second-Order injections (`BLOCKED_STORED_DB_INJECTION`). | `LLM01:2025` (Second-Order Stored Injection) |
| **Layer 3c: Zero-Trust SSRF Egress Guard** | `src/guardrails.py` (`validate_safe_egress_url`) | Enforces `https://`, blocks loopback/private/link-local (`169.254.0.0/16`) IPs (including IPv4-mapped IPv6 `::ffff:169.254.169.254`) via `ipaddress`, and enforces an explicit domain allowlist (`BLOCKED_SSRF_EGRESS_GUARD`). | `LLM06:2025` (Agentic SSRF) |
| **Layer 4: SQLite C-Driver Authorizer** | `src/tools.py` (`_hr_sqlite_authorizer`) | Enforces `sqlite3.SQLITE_DENY` inside the SQLite engine at query compilation time if any statement references `board_salaries` or attempts non-`SELECT` operations (`DELETE`, `UPDATE`, `DROP`, `PRAGMA`). | `LLM06:2025`, `LLM02:2025` |
| **Layer 5: Dynamic Database-Backed Output DLP & Media Sanitizer** | `src/guardrails.py` (`inspect_and_sanitize_output`) | Dynamically loads protected executive records from SQLite (`_load_protected_entities_from_db`), scans for Canary Honeytoken patterns (`CONF-HR-9921-X`, `CANARY-CLOUD-IAM-KEY-*`), and neutralizes external Markdown/HTML media tags (`<img>`, `<iframe>`, `<script>`). | `LLM02:2025`, `LLM05:2025` |
| **Layer 6: Local Tamper-Evident SHA-256 SIEM Chain** | `src/telemetry.py` (`verify_telemetry_integrity`) | Links every JSONL telemetry event via canonical SHA-256 digests (`prev_hash` -> `event_hash` from `GENESIS_HASH`), verifying internal chain consistency against record modification or deletion. | Post-Incident Log Modification / Deletion |

## 4. Scope of Security Claims & Known Limitations

An empirical benchmark result of **`0.0% ASR`** on the laboratory test suite (`ATK-01` through `ATK-08`) **does not imply immunity to all possible LLM attacks**. Reviewers should account for the following methodological and architectural boundaries:

1. **Normal Execution vs. Deterministic Boundary Routing (`_route_hardened_tool_boundaries`):**
   - **Normal Execution (`evaluation_mode=False`, default):** The model independently decides whether to invoke an available tool; the test router does not intervene in the control flow.
   - **Security Evaluation (`evaluation_mode=True`):** Deterministic Boundary Routing is an evaluation-only fallback used to exercise backend security controls when a small local model (`qwen2.5:3b`) does not emit native structured tool calls. Its results are reported separately from natural model tool-calling behavior and are treated as verification of backend boundary enforcement rather than evidence of model-level attack resistance.
2. **SHA-256 Hash Chain — Internal Integrity, Tail Truncation & External Authenticity:**
   - **Integrity Checking (Internal Consistency):** The verifier detects in-place record modification, reordering, and deletion of intermediate log entries. It cannot independently detect truncation of the final log entries or complete log deletion, because an empty log is currently treated as a valid `EMPTY_LOG` state. Detecting these cases requires an externally stored checkpoint or trusted expected tail hash.
   - **Authenticity & External Trust:** Because `GENESIS_HASH` is a public constant in code and logs are stored locally, an attacker with write access to the host filesystem could rewrite the entire `data/telemetry.jsonl` file and recompute all hashes from the beginning. Full forgery resistance requires an external trust anchor: `HMAC-SHA256` with a hardware-protected secret key, periodically exported/signed external checkpoints, or streaming to a remote append-only SIEM storage.
3. **Heuristic Token Estimation & In-Memory Rate Limiting State:**
   - `estimate_token_count()` uses deterministic character-density and word-boundary heuristics as an approximate input-size metric rather than a model-specific BPE tokenizer. Furthermore, `check_unbounded_consumption()` stores sliding-window history in process memory (`_CONSUMPTION_WINDOW`), meaning limits are enforced per Python worker rather than globally across a multi-worker or distributed deployment.
4. **Simulated Cloud Metadata & Production SSRF Defense Requirements (`ATK-08`):**
   - `fetch_portfolio_url` simulates IMDSv1 access locally by routing metadata requests to `127.0.0.1:8888` or returning a synthetic `ASIA-...` payload. In `Hardened` mode, `validate_safe_egress_url()` validates the URL scheme, IP literals, and a static domain allowlist (`github.com`, `gitlab.com`, `linkedin.com`).
   - However, application-layer hostname allowlisting (and even a single pre-request DNS check) does not fully mitigate **DNS Rebinding** if the HTTP client performs a second, independent DNS lookup when opening the socket. Complete production SSRF protection requires: (a) resolving DNS once, (b) validating all returned IP addresses against private/link-local ranges, (c) connecting directly to the validated IP without a second DNS lookup while preserving proper TLS SNI and certificate hostname verification, (d) re-validating or disabling HTTP redirects (`allow_redirects=False`), and (e) enforcing network-layer VPC egress rules.
5. **Turn-Scoped Tool Omission & In-Scope Semantic Manipulation:**
   - Setting `tools=None` when `cv_attached=True` omits tool declarations from that specific provider request, preventing the model from emitting tool calls for that turn while the backend dispatcher independently enforces authorization. Additionally, `<untrusted_cv_data>` XML tags are structural aids, and backend access controls do not block purely semantic persuasion within authorized resume fields.
